and packs. Record git HEAD, dirty diff digest, binary/pack digests, SDK and ME

4. PPSSPP: isolated Slim profile, 100% speed, frame skip/auto/fast-forward off,

Instrumentation contract
------------------------
One monotonic time base extended across 32-bit wrap; separate wake epochs. Per
thread fixed-size buffers, sequence numbers, overflow and total counts, no
heap/file logging on output/mixer/GE submission. Flush stopped windows or use
bounded low-priority draining whose cost is measured. Compact record layout:
version, timestamp_us, thread, event, tick_id, pass_id, scene_epoch, request
or actor_instance_id, values. Bind generation to reused framebuffer addresses
and asset slots. Correlate worker completion via IDs. Reuse OOTDEBUG metrics
only after wiring and verifying MM boundaries. PSP_AUDIO_DIAGNOSTICS=1,
PSP_GFX_DIAGNOSTICS=1, PSP_WAKE_DIAGNOSTICS=1 are separate diagnostic builds;
compare CPU cost, trace loss and wall time against release.

Capture simulation, actor constructor/free, update, skeletal animation,
collision/AI, DL build/interpret/submit, GE fence and vblank wait; bytes read,
seek, lock, parse/transform/decode/upload, hit/miss, priority, queue age/depth,
idle-with-demand, eviction and cancel; audio producer/ME publish/output return,
PCM occupancy and error/underrun/late counters; arena/list peak and available
largest block. Tag assets requested, read, CPU-ready, animation/material-ready,
GE-safe, audio-ready and first required tick. Unavailable dependencies still
count as late when they suppress first use. Use IDs for expected visible
actors and native scripted reveals. Hash explicit stable logical fields at
fixed input ticks (position/health/clock/quest flags/room/cutscene, RNG if
controlled); exclude pointers, padding and rendering state. Check button edge
to first game response latency in ticks plus display latency in wall time.

Off-device compute mean/p50/p95/p99/max for work and present deltas per route
segment/run. Use start-to-ready critical path, exclude pacing sleep and display
idle, report overlapped game/ME/GE spans separately; never add overlapping
thread timers. Amortize game tick work across actual passes and also show slow
individual passes. Report count/fraction over 25 ms, clusters and intervals
over 50 ms, slowest 10 s window, actual game ticks/s, rendered passes/s,
unique fronts/s and repeated fronts. A framebuffer queued for next refresh
is distinct from a verified displayed frame. Label lower bounds if scanout
cannot be observed for every vblank. Measure GPU wait as a wait proxy unless
true execution timing is available. Correlate p99 stalls with trace events.
Report read throughput and service latency separately. For each request compute
ready slack = first required time minus ready time. Summarize queued/driver
audio latency, audio-clock drift and PCM discontinuities, listen to route clips.

Acceptance on the PSP-3000
--------------------------
* Normal game divisor 3 at nominal 60 VI/s yields ~20 updates/s. Goal 40 unique
  renders/s and 40 unique fronts/s in sustained moving gameplay, average work
  <=25.0 ms; use measured refresh*2/3 for the nominal 40 scanout tolerance.
  Report each trial and full steady-gameplay window, worst 10 s and p95/p99/max.
  Propose no regression in tails versus paired trials beyond measured variability
  and zero identifiable actor-I/O-only over-budget passes. Show counts even when
  a goal is missed. With VSync expect roughly 16.7/33.3 ms holds; also report
  excess three-or-more-refresh holds. VSync-off tearing is a separate tradeoff.
* Audio: zero unintended silence, pop/click/dropout and mixer/output underruns
  in all cold/warm routes and >=20 min soak. Report initial priming and explicit
  pause/wake recovery separately. Check pitch, stereo, tempo, sustained notes,
  output errors, latency and minimum playable occupancy. Intentional rests in
  the score need clip corroboration. Zero counters alone cannot prove quality.
* Streaming: zero deadline misses that starve audio or visible assets; aim for
  eligible critical queue service within 25 ms or its earlier audio deadline.
  Report p95/p99/max service, media latency and hidden latency separately.
  Zero unexplained pop-ins on camera turns/spawns/doors/effects; trace expected
  first use and compare original reveal. Document timeouts, retries and dropped
  trace records. Missing trace intervals cannot support a zero-event claim.
* Logic: same expected quest, timer, collision, cutscene, animation and save
  results on a deterministic route at 20/40/60. Input responsiveness and A/V
  sync must hold. Visual rows require clip/still evidence, plus no lost effect.
* Memory/stability: no crash, corrupted bytes/save, missing mandatory assets,
  unbounded waits or increasing retained allocations across identical cycles.
  Compare RAM, EDRAM, largest usable block, peaks at transition overlap and after
  teardown; preserve measured worst-case baseline headroom. Report failures.
* Archive results per step under an external evidence root, e.g.
  ~/PocketMajora-evidence/step-01/{before,after}/<device>/<run>/ with
  manifest.txt, route.txt, events, metrics.csv, state hashes and AV indices.
  Store private inputs locally; include paths/checksums and compact results
  in HANDOFF.txt. No target machine means hardware-pending, never accepted
  as a device performance fix. If infeasible identify measured constraints,
  remaining milliseconds and choices for the user; keep 40 as requested.
