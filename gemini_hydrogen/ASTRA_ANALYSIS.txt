Capacity ledger | allocations and limits, not measured peaks
-----------------------------------------------------------
64 MiB model + MEMSIZE=1 in Makefile.psp. 8 MiB system arena reserved independent
of 1 MiB newlib heap. Main stack 256 KiB, callback 4 KiB, audio out 64 KiB,
generation 128 KiB, video 64 KiB. Object_InitContext uses 1380/1470/1530/1580
KiB inside game-state allocation depending on scene. Do not add it twice.
Audio ring 16384 stereo s16 frames = 64 KiB, two 768-frame outputs = 6 KiB,
external audio pool 2 MiB, plus ME state and AI buffers. Loader constants
include 2 MiB asset window size, 64 KiB packed blocks, 4 MiB packed cache
target/1 MiB minimum, 128 KiB direct-read chunks. Pinned caches include
audiotable, audiobank, audioseq, link_animation, kanji, do_action. Targets may
shrink/fail; inspect actual allocations and volatile ownership on each run.

gfx_scegu.c:2060,2258-2358 selects EDRAM dynamically (2 MiB floor, DVE/4 MiB
path). 512x272 LCD with 3 color and 1 depth buffer costs 1,114,112 bytes at
16-bit color or 1,949,696 at 32-bit color, before shadow (64x64x4), padding,
textures. 768-wide TV uses 2 color buffers with interlaced height handling;
240p at narrow stride takes the triple path. Texture manager cap 1.25 MiB in
psp_texture_manager.h:17; storage is RAM for the TV-capable allocation path.
Three RAM background surfaces sized from maximum supported geometry plus
on-demand motion blur storage; count mode-specific costs even on LCD. Record
actual list/vertex high water, texture pool, BSS, stack slack, free and largest
block at boot, transition overlap, busy scene, after teardown and wake.
Reserve at least baseline worst observed demand plus measured transient overlap
and audio needs before allocating speculative work. Absolute additional safe
budget currently unknown. If contiguous headroom is insufficient, shed optional
prefetch/cache bytes first and retry required requests at the legal transition.

Hypotheses in implementation order | all NEED TEST unless stated
---------------------------------------------------------------
1. Measurement bias. oot_psp_performance.c:156,257,320 aggregates 60-frame
windows under OOTDEBUG; active MM frame boundaries lack those begin/end calls.
MmPsp_DiagLog:130 serializes open/append/close per logged event and is called
from object-load and pending-actor paths. INFERRED logging can itself hitch.
Use bounded per-thread events and deferred flush; alternatively sample fewer
spans. Cost is trace RAM/CPU; overflow makes windows incomplete. Compare
tracing on/off, latency with/without synchronous diagnostic writes. A negligible
difference rejects logging as a cause. Gain sought is attributable measurements.

2. Audio deadline. AudioThread_UpdateImpl waits for DMA and ME ownership;
TryRunUpdate now also drains completion immediately after update. OutputThread
injects silence and re-primes below one source chunk. A miss in the pinned
audio window falls through to loader semaphore; urgent reads bypass the
foreground wait but still need the lock. INFERRED misses can starve already
playable PCM. Trace buffer trough vs ME/producer/cache/driver events. First
bound the proven wait/advance publication; alternatively preload measured bank
windows. Cost extra bandwidth/RAM or latency, risk cache incoherence or hiding
starvation by muting. Expect zero gaps; full occupancy across audible glitches
falsifies supply starvation; inspect resampler endpoints/voice data instead.

3. Display/save correctness. gfx_scegu.c:2489-2517 waits repeatedly for
sPendingBuffer without checking query/queue success; video waiter can block.
A rejected flip is sufficient in a fault harness; occurrence on device unknown.
Check return values, bound recovery and safely reacquire buffer ownership;
fallback is a drained mode reset. Save flush truncation can destroy the last
good image; use validated temp + recoverable previous generation after testing
FAT rename semantics. Alternative double-slot protocol with legacy import.
Costs transitional storage and extra I/O, risk stale buffers/wrong generation.
Inject failure at each boundary; a correctly recovered prior/complete save
and eventual worker release refute the proposed failures after the patch.

4. I/O convoy. mm_psp_game.c:467 RequestAsync does read before notifying.
oot_psp_asset_loader.c:347,830,1062,2679 shares sought file position, locks
and cache slots. libultra_psp.c:500-551 uses 1 ms delays for blocking queue
retries. load.c:1262,1740,1884 changed sync/slow/async batch sizes. First
prefetch validated VROM ranges into owned staging; introduce bounded worker
only where inline demand still dominates. Never unlock while holding a live
evictable pointer. Larger transfers can improve throughput and extend tail
latency. Trace bytes/seek/cache hit/lock wait and first-use slack. If all hot
ranges were ready and frames still hitch, further read-ahead cannot help.

5. Actor/visibility. Constructors and ZeldaArena_Malloc run inline, pending
banks delay init, materials can import on first draw. Shared culling flags
affect update eligibility. INFERRED CPU visibility in widescreen, delayed
object readiness, or unmatched interpolation may each look like pop-in.
Warm only measured immutable dependencies of an upcoming actor, separate
draw-only projection correction when demonstrated. Consider instance pooling
only after allocator timing proves expensive. Costs live memory/draw calls;
wrong lifetimes can change schedules or leak identities. Record per-actor
ready/init/cull/first drawn + capture. On-time assets and correct projection
redirect investigation to room clipping, material state or source-native reveal.

6. Renderer throughput. Two passes call RenderTask on the same display list
with different fractions. gfx_fast3d.c:2155,2904,4774,5970 and GU submission
do repeated lookups, conversion or state work depending on material. Native
mesh caching, batches and fast paths already exist. Measure second-pass CPU,
flushes, GE wait, texture imports, actor ticks and idle separately. Reuse only
immutable work with generation-aware keys; second choice is reduce measured
state flushes, retaining translucent order. Costs memory and invalidations;
wrong keys corrupt animated water, palettes or reused actor addresses. If GE
fill or original game update dominates, abandon replay caching and address
that measured stage. Only a real moving-scene trace can estimate gain.

7. Cadence and parity. A paced 25 ms start can coincide with an occupied draw
buffer; 60 Hz scanout must alternate refresh holds. Compare deadlines to GE
finish and actual front buffer; tune only avoidable wait. Optionally improve
safe transform coverage if intermediate screenshots show snapping. Advancing
feedback twice per tick can change blur decay; compare time-matched captures.
Remedies cost history memory, validation and potentially passes. No increase
in unique moving frames or unchanged visual error falsifies benefit.
See parity matrix for individual effect and state tests. Never count suppressing
a layer, skipping simulation or clipping more of a scene as an improvement.

Quantitative gains before device tracing are unknown. Priorities above use
source-proven mechanisms, impact of failure, and reversibility. Branch to the
dominant measured cost if breakouts invalidate a hypothesis. Reconcile all
changes with flash, HOME, video settings, sleep and asset generation on wake.

Additional blocking sites to distinguish in the trace
----------------------------------------------------
* gfx_scegu_reserve_list_memory finishes and synchronizes a full list;
  gfx_scegu_sync_texture_cache fences reuse on eviction. gfx_scegu_read_depth
  joins the video worker before reading even one depth result. Attribute a wait
  to its caller, list occupancy and material, rather than to generic GPU time.
  gfx_psp_submit.h caps vertex arena at 2 MiB, list at 256 KiB, batches at
  12 draws / 220 triangles. Record rollovers, inline bytes and 64-byte-aligned
  vertex consumption. First try reducing measured redundant state/imports;
  dependent depth queries must see the correct completed image. Defer a read
  only if equivalent tick semantics are established. Few rollovers/short joins
  rule this out as the dominant cost.
* Play_LoadFile (src/code/z_play.c:1652ff) tail-allocates and performs synchronous
  scene DMA. On a cache miss storage can dominate this boundary. Room meshes
  and objects have separate request and activation boundaries. Keep these
  timings distinct from overlay/state malloc/free, first texture swizzle,
  motion-blur allocation, synchronous save flush and optional diag log writes.
* OotPspAudio_Update (backend/oot_psp_audio_backend.c:3608) runs updates on the
  game thread if the producer thread is absent. Distinguish producer startup
  failure from CPU mixing fallback, which can still run on the producer.
  Record thread creation result and actual thread ID for each update. A missed
  60 Hz producer tick does not by itself imply an audible outage.
* Stack usage, full-screen history, GE texture storage fallback and packed asset
  cache occupancy must be measured concurrently. Set optional allocation quota
  from the smaller of spare total bytes and contiguous bytes above the largest
  future mandatory allocation observed on the transition route. Stress with
  allocation failure and verify correct recovery before admitting more prefetch.
