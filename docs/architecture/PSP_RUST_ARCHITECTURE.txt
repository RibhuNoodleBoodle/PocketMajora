3. QUANTITATIVE PSP-3000 MEMORY & VRAM BUDGETS
----------------------------------------------------------------------
PSP-3000 has 64 MiB physical DRAM (Partition 2 User memory provides ~50-52 MiB usable
when `MEMSIZE=1` is set in `PARAM.SFO`) plus 2 MiB embedded eDRAM (VRAM at `0x04000000`).

A) 2 MiB VRAM (`0x04000000` - `0x041FFFFF`, 2,097,152 bytes) Allocation Map:
  +----------------------------------------+---------------+-------------+---------------+
  | Buffer Purpose                         | Dimensions    | Pixel Fmt   | Size (Bytes)  |
  +----------------------------------------+---------------+-------------+---------------+
  | Draw Buffer 0 (LCD Triple Buffer #0)   | 512 x 272     | PSM_5650(2B)|       278,528 |
  | Display Buffer 1 (LCD Triple Buffer #1)| 512 x 272     | PSM_5650(2B)|       278,528 |
  | Display Buffer 2 (LCD Triple Buffer #2)| 512 x 272     | PSM_5650(2B)|       278,528 |
  | Hardware Z-Buffer (16-bit Depth)       | 512 x 272     | ZBUPSM_16(2)|       278,528 |
  | GPU Motion-Blur History / FB Effect Buf| 512 x 272     | PSM_5650(2B)|       278,528 |
  | Hot Texture / TLUT Scratch Slot in VRAM| Variable      | 4/8/16/32b  |       704,512 |
  +----------------------------------------+---------------+-------------+---------------+
  | TOTAL VRAM COMMITTED                   |               |             |     2,097,152 |
  +----------------------------------------+---------------+-------------+---------------+
  * Note: 16-bit `GU_PSM_5650` triple-buffering + 16-bit Z + 16-bit motion-blur history
    takes `5 * 278,528 = 1,392,640` bytes (~1.33 MiB), leaving `704,512` bytes (~688 KiB)
    of fast VRAM for hot render-to-texture / TLUT / tile uploads. If 32-bit `GU_PSM_8888`
    is selected in double-buffer mode (`2 * 557,056 + 278,528 = 1,392,640` bytes), the
    exact same 688 KiB VRAM headroom remains.

B) 64 MiB System DRAM (Partition 2 User Space: ~50 MiB Usable) Budget:
  +----------------------------------------------------+------------+--------------------+
  | Memory Region / Pool                               | Budget     | Backing Mechanism  |
  +----------------------------------------------------+------------+--------------------+
  | EBOOT `.text`, `.rodata`, `.data`, `.bss` + Stack  |   4.0 MiB  | ELF Load + 256K Stk|
  | Rust `psp` Default Static Heap (`SIMPLE_ALLOCATOR`)|   8.0 MiB  | `rust-psp` `A8M`   |
  |   - `GameState` (`PlayState` / `FileChoose`)       |  (2.5 MiB) |                    |
  |   - Double-buffered GBI `GfxPool` (`2 * ~256 KiB`) |  (0.6 MiB) |                    |
  |   - Actor instances, BgCheck dyna poly, strings    |  (4.9 MiB) |                    |
  | Kernel Block 1: Permanent Common Assets            |   6.0 MiB  | Partition 2 Block  |
  |   - `pmm_2s2h.pak` index table (~512 KiB)          |            |                    |
  |   - `gameplay_keep`, `parameter_static`, fonts,    |            |                    |
  |     `message_data_static`                          |            |                    |
  | Kernel Block 2: Scene + Room + Object Arena        |   8.0 MiB  | Partition 2 Block  |
  |   - Active Scene (`gSegments[2]`) + 2 Room slots   |            |   (Slab/Double-End)|
  |     (`gSegments[3]`) + Object slots (`ObjectContext`)|          |                    |
  | Kernel Block 3: Renderer Native Mesh & Tex Cache   |   6.0 MiB  | Partition 2 Block  |
  |   - 2x 512 KiB GE Command Lists (`sceGuStart`)     |  (1.0 MiB) |   (64B aligned)    |
  |   - Converted PSP texture cache + CLUT tables      |  (3.0 MiB) |                    |
  |   - Cached static room PSP vertex buffers (36B/vtx)|  (2.0 MiB) |                    |
  | Kernel Block 4: Audio Sample & Synthesis Pool      |   8.0 MiB  | Partition 2 Block  |
  |   - MM `Audiotable` streamed/pinned sample bank    |  (5.5 MiB) |                    |
  |   - `Audiobank` + `Audioseq` + 32 kHz PCM ring     |  (2.5 MiB) |                    |
  | Safety / Firmware / Fragmentation Headroom         | ~10.0 MiB  | Unallocated User   |
  +----------------------------------------------------+------------+--------------------+
  | TOTAL USER PARTITION TARGET                        |  40.0 MiB  | Out of ~50-52 MiB  |
  +----------------------------------------------------+------------+--------------------+
  * Fragmentation Rule: All blocks >= 256 KiB are allocated once at boot via
    `sceKernelAllocPartitionMemory` and sub-allocated via deterministic generation/ring/LRU
    arenas. Runtime `malloc`/`free` churn during gameplay frames is forbidden.

4. CRITICAL HARDWARE & ENGINE SUBSYSTEM DESIGNS
----------------------------------------------------------------------

A) Segmented Addressing & 2S2H Resource Resolution (`crates/pmm-schema`, `crates/pmm-assets`)
   - In 2S2H, pointers passed to display lists, scene headers, collision, and skeletons are
     either:
     1) N64 segmented addresses `0x0s000000`..`0x0FFFFFFF` (`s = 0..15`), resolved via
        `gSegments[s] + offset`, OR
     2) 2S2H symbolic asset paths (`"__OTR__..."`) or 64-bit resource handles.
   - On 32-bit MIPS Allegrex:
     * PSP user-space RAM resides at `0x08800000`..`0x0BFFFFFF` (cached) and
       `0x48800000`..`0x4BFFFFFF` (uncached).
     * Notice that N64 Segment `0x08`, `0x09`, `0x0A`, `0x0B` (`0x08000000`..`0x0BFFFFFF`)
       OVERLAP numerically with PSP native user-space pointers (`0x08800000`..`0x0BFFFFFF`)!
     * Solution (incorporating the lesson from `psp_ref/src/port/psp/mm_psp_game.c:27-29`):
       In our Rust port, we represent asset references as typed `AssetRef` / `ResourceId(u64)`
       hashes in Rust structs, and when interpreting raw F3DEX2 `Gfx` 64-bit words:
       - Segment IDs `0x01`..`0x07` and `0x0C`..`0x0F` with small offsets (`< 0x01000000`)
         look up `g_segments[seg]`.
       - Any native pointer inside the `pmm-assets` arenas (`0x08800000`..`0x0BFFFFFF`) is
         distinguished from segment `0x08`..`0x0B` by checking whether `g_segments[seg]` is
         populated and offset `< segment_size[seg]` vs a direct arena pointer, or by tagging
         `Gfx` resource references with opcode/high-bit markers at pack compilation time in
         `tools/pmm-extractor`.

B) Big-Endian N64 Assets on Little-Endian MIPS (`tools/pmm-extractor`)
   - N64 ROMs are big-endian (`.z64`) or byte/word-swapped (`.v64`/`.n64`).
   - PSP Allegrex is strictly little-endian (`mipsel-sony-psp`) and faults (`ADEL`/`ADES`)
     on unaligned 16/32-bit loads/stores.
   - `tools/pmm-extractor` performs ALL byte-swapping and struct alignment on the host PC
     when building `pmm_2s2h.pak`. Every resource payload in `pmm_2s2h.pak` starts at a
     16-byte aligned file offset so it can be read directly into 16-byte aligned PSP RAM
     buffers without per-field runtime byte-swapping.

C) F3DEX2 -> PSP `sceGu` Renderer (`crates/pmm-gfx`)
   - Microcode: Majora's Mask uses `F3DEX2` (`GBI_UCODE = F3DEX_GBI_2`).
   - Vertex Pipeline:
     * N64 `Vtx` is 16 bytes (`s16 ob[3]`, `u16 flag`, `s16 tc[2]`, `u8 cn[4]`).
     * Converted at load/pack time or on first use into PSP native vertices (`GU_TEXTURE_32BITF |
       GU_COLOR_8888 | GU_NORMAL_8BIT | GU_VERTEX_32BITF`).
     * Static opaque/translucent display lists are cached as immutable PSP vertex arrays in
       the 2.0 MiB mesh cache; dynamic skinned meshes (Link, NPCs) write into the per-frame
       uncached GE vertex ring buffer.
   - Transform, Precision & Z-Buffer:
     * N64 uses 16.16 fixed-point `Mtx` (64 bytes). `pmm-gfx` converts `Mtx` to `ScePspFMatrix4`
       (`f32` 4x4) and multiplies/projects via Allegrex VFPU (`vfpu_asm!`).
     * PSP GU hardware clips badly when geometry crosses behind the camera (`z < near`).
       `pmm-gfx` clips triangles spanning the near/frustum planes in software/VFPU before
       emitting `sceGuDrawArray`.
     * PSP GU depth buffer is reversed (`0xFFFF` near, `0x0000` far) or configured via
       `sceGuDepthRange(65535, 0)` with `sceGuDepthFunc(GU_LEQUAL)` and `GU_CLIP_PLANES`
       enabled; decal surfaces (`ZMODE_DEC`) apply a small `sceGuDepthOffset`.
   - Texture Codecs & TMEM Emulation:
     * N64 formats: `RGBA16` (5551), `RGBA32` (8888), `CI4` (4-bit paletted), `CI8` (8-bit
       paletted), `IA4`, `IA8`, `IA16`, `I4`, `I8`.
     * PSP `sceGu` natively supports `GU_PSM_5551`, `GU_PSM_8888`, `GU_PSM_T4` (`CI4`), and
       `GU_PSM_T8` (`CI8`) with hardware CLUT (`sceGuClutLoad`)!
     * `IA4`/`IA8`/`IA16`/`I4`/`I8` textures are pre-expanded by `tools/pmm-extractor` (or
       cached on first upload in `pmm-gfx`) into `GU_PSM_4444` or `GU_PSM_8888` swizzled
       PSP textures (`GU_TRUE` swizzle for 2x-4x PSP texture fillrate).
     * Clock Town 12-bit wrapped tile bounds and multi-tile scrolling UVs are normalized
       consistently before emitting `sceGuTexScale` / `sceGuTexOffset`.
   - Combiner & Motion Blur:
     * Single-pass RDP color combiners map to `sceGuTexFunc(GU_TFX_MODULATE / DECAL / BLEND /
       REPLACE)` + `sceGuTexEnvColor`. Two-cycle materials emit a second blended pass when
       needed.
     * Motion blur uses a GPU-resident history buffer in VRAM (`0x04110000`) blended via
       unlit 32-pixel vertical strips and captured prior to HUD rendering via `sceGuCopyImage`,
       requiring zero CPU framebuffer readback.

D) 40 FPS Frame-Interpolated Presentation + 20 Hz Game Simulation (`crates/pmm-game`, `crates/pmm-gfx`)
   - Owner Target: **40.0 FPS** (`25,000 us` per presented frame = `2x` the original 20 Hz N64 logic rate).
   - Why 20 Hz Simulation + 40 FPS Matrix Interpolation (`2 passes/tick`) is Mandatory:
     * Majora's Mask actor schedules (`z_en_hy`), physics impulses, animation frame counters,
       cutscene timers, and the 3-Day Clock (`gSaveContext.save.time += R_TIME_SPEED`) are
       hardcoded for 20 Hz (`50,000 us`) integer ticks. Doubling logic tick rate would double
       game speed or break integer velocities/timers.
     * Instead, adapting 2S2H's `FrameInterpolation` (`majora_code/mm/2s2h/Enhancements/FrameInterpolation/`)
       and `psp_ref`'s transform-history design (`oot_psp_frame_interpolation.c`, `mm_psp_scheduler.c`),
       each 20 Hz logic tick generates ONE immutable `GfxMasterList` and records world-space
       model/view/limb `MtxF` transforms keyed by `(entity_identity, call_site)` into a
       double-buffered `FrameHistory` table (`2048` matrix slots, ~300 KiB static storage).
     * The scheduler then renders **2 passes per 20 Hz tick** (`25,000 us` deadline each):
       - **Pass 0 (`fraction = 0.5`, `+25,000 us`):** Replays the display list while blending
         each matched matrix `M(0.5) = M_prev + (M_curr - M_prev) * 0.5` via VFPU (`lv.q`,
         `vsub.q`, `vscl.q`, `vadd.q`).
       - **Pass 1 (`fraction = 1.0`, `+50,000 us`):** Replays the display list with the
         authoritative `M_curr` matrices.
     * **Teleport / Cut / Singular-Matrix Guard:** History resets immediately on game-state,
       scene, room, or camera-cut transitions. Individual matrix pairs skip interpolation
       (snapping to `M_curr`) if translation delta squared `> 1000.0^2`, any basis row dot
       product `<= 0.0` (>90 deg flip), or scale ratio changes by `> 4x`.
     * **Five Hardware Optimizations Required from Day 1 to Sustain 40 FPS (`25 ms/frame`):**
       1. `scePowerSetClockFrequency(333, 333, 166)` locked at boot in Step 02 (`+50%` CPU/bus).
       2. Pre-swizzled PSP 16x8 textures (`GU_TRUE`) produced by `tools/pmm-extractor` in Step 03
          and cached in `pmm-gfx` in Step 05 (`2x-4x` GE texture fillrate).
       3. Pre-compiled native PSP GE command lists (`sceGuCallList`) + 36-byte vertex buffers
          for static room `SetMesh` display lists in Pool 3 (`RendererCache`), so static room
          geometry requires zero F3DEX2 re-decoding or CPU vertex copying during Pass 0 and Pass 1.
       4. Redundant state-binding suppression in `pmm-gfx` (tracking active texture, CLUT,
          combiner, and blend state so consecutive sub-meshes with identical materials emit
          only `sceGuDrawArray`).
       5. Inline Allegrex VFPU (`vfpu_asm!`) for 4x4 matrix multiply (`vmmul.q`), midpoint
          matrix lerp (`fraction = 0.5`), and frustum plane dot products starting in Step 05/06.

E) Audio Architecture (`crates/pmm-audio`)
   - MM synthesizes audio at 32,000 Hz (`32 kHz`), 16-bit stereo (`533` or `544` samples per
     60 Hz sub-frame, `1,600` samples per 20 Hz game tick).
   - `pmm-audio` runs a dedicated PSP kernel thread (`sceKernelCreateThread`, priority `0x12`)
     that consumes ABI command lists generated by the game thread, decodes VADPCM samples from
     the Audio Pool, mixes/resamples to 44,100 Hz (or outputs via `sceAudioSRCChReserve(samples,
     32000, 2)` hardware sample-rate conversion), and blocks on `sceAudioSRCOutputBlocking`.
   - Note: Using PSP's built-in hardware sample-rate converter (`sceAudioSRCChReserve` at
     `32000` Hz) avoids software resampling overhead on Allegrex!

F) Save Data (`SysFlashrom` / `SaveContext`)
   - Original MM uses a 128 KiB (`0x20000` byte) Flashrom (`mm-psp-save.bin`), split into
     primary/backup save slots (`Newf` magic) and owl-statue temporary saves.
   - `pmm-game` implements the exact asynchronous state machine (`SysFlashrom_WriteAsync` ->
     `SysFlashrom_IsBusy` -> `SysFlashrom_AwaitResult`) backed by atomic write-to-temp +
     rename (`mm-psp-save.tmp` -> `mm-psp-save.bin`) on `ms0:`/`ef0:`.

G) Sleep / Resume, HOME Exit & Crash Logging (`src/platform/`)
   - HOME Exit Callback: Signals an `AtomicBool` (`EXIT_REQUESTED`) so the main loop cleanly
     flushes any pending save, stops audio/GU, writes shutdown status, and calls
     `sceKernelExitGame()`.
   - Power Suspend / Resume Callback:
     * On `PSP_POWER_CB_SUSPENDING` / `PSP_POWER_CB_STANDBY`: Pauses the game & audio threads,
       waits for `sceGuSync`, records current file offsets, and closes open `ms0:`/`ef0:`
       file descriptors (`pmm_2s2h.pak`) because PSP firmware invalidates Memory Stick file
       descriptors across sleep!
     * On `PSP_POWER_CB_RESUME_COMPLETE`: Re-opens `data/pmm_2s2h.pak`, restores GU context
       and textures, resets frame-pacing RTC delta, and resumes gameplay.
   - Panic & Crash Handler:
     * Custom Rust `#[panic_handler]` (or `std::panic::set_hook` via `rust-psp`) formats the
       panic location/message, appends it to `ms0:/PSP/GAME/PocketMajora/crash.log` via raw
       `sceIoOpen`/`sceIoWrite`/`sceIoClose`, displays the error on the PSP screen via
       `psp::dprintln!`, waits 5 seconds (or for button input), and exits cleanly via
       `sceKernelExitGame()`.
