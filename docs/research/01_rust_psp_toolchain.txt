----------------------------------------------------------------------

   - Versions:   `psp = "0.3.14"`, `cargo-psp = "0.2.10"` (published on crates.io)

B) Modernized Fork: `AndrewAltimit/rust-psp` (SELECTED)
   - URL:        https://github.com/AndrewAltimit/rust-psp
   - Docs:       https://andrewaltimit.github.io/rust-psp/
   - Pinned SHA: `e4cc06f6fa50fa45dc3ae8b332e8a2b67625f588` (`main`)
   - Versions:   `psp = "1.0.0"`, `cargo-psp = "1.0.0"` (Git-only; NOT on crates.io)
   - Edition:    Rust 2024
   - License:    MIT
   - Pinned CI Nightly (`rust-toolchain.toml`):
     * `channel = "nightly-2026-04-13"`
     * `components = ["rust-src"]`
     * Minimum supported rustc enforced by `cargo-psp`: 1.87.0 (2025-03-18).
   - Allocator (`psp/src/alloc_impl.rs`):
     * Reserves a single 8 MiB userspace arena (`HEAP_SIZE = 8 * 1024 * 1024`)
       from `SceKernelPrimaryUserPartition` (Partition 2) on first allocation
       and runs `linked_list_allocator::Heap` over it, avoiding the 1,500-block
       PSP firmware hang.
     * Allocations `>= 256 KiB` (`LARGE_ALLOC_THRESHOLD`) or overflow allocations
       automatically bypass the 8 MiB arena and allocate dedicated blocks from
       `SceKernelPrimaryUserPartition` via `sceKernelAllocPartitionMemory`
       (tagged with `TAG_KERNEL = 0xC0DE_BABE` and freed on `dealloc`).
     * Uses a scheduler-yielding spinlock (`sceKernelDelayThread(100)`) so
       multi-threaded audio/I/O priority inversion cannot deadlock the heap.
     * Exposes `psp::mem::PartitionAlloc<UserPartition, T>` and
       `psp::mem::alloc_user_bytes(size, name)` for explicit partition-2 blocks.
   - Syscall & Subsystem Coverage:
     * 837 firmware imports (`psp::sys`), full PSP GU (`sceGu*`) + GUM
       (`sceGum*`), `psp::vram_alloc` (2 MiB EDRAM allocator), `psp::input`
       (`Controller`, `enable_analog`), `psp::io` (`File`, `IoOpenFlags`),
       `psp::audio` / `psp::audio_mixer`, `psp::power`, `psp::rtc`, `psp::time`,
       `psp::savedata`, `psp::callback`, `psp::sync`, and `vfpu_asm!`.
   - `no_std` + `alloc` vs `std`:
     * Default mode (`#![no_std]`, `#![no_main]`, `extern crate alloc`) supports
       `Vec`, `String`, `Box`, `BTreeMap`, and unwinding panics (`catch_unwind`)
       with smaller binary size and zero host-OS assumptions.
     * Experimental `features = ["std"]` exists, but `no_std` + `alloc` is
       preferred for the PSP runtime to keep full control over memory, I/O, and
       binary footprint.

2. COMPILER, LINKER, AND PSPSDK INDEPENDENCE
----------------------------------------------------------------------
* Target Triple: `mipsel-sony-psp` (built into `rustc` nightly; little-endian
  MIPS Allegrex r4000-derivative with single-precision FPU and VFPU).
* No C PSPSDK Required for Pure Rust:
  `cargo psp` invokes `cargo build --target mipsel-sony-psp -Z build-std=core,compiler_builtins,alloc,panic_abort,panic_unwind`,
  runs `fix_imports` on the linked ELF, converts ELF -> PRX via `prxgen`,
  generates `PARAM.SFO` via `mksfo`, and packs `EBOOT.PBP` via `pack-pbp`.
* Mandatory Cargo Patch:
  `unicode-width` 0.2.x uses `#[repr(align(128))]` lookup tables that cause
  PRX relocation failures ("Garbage libstub address"). Root `Cargo.toml` MUST
  include:
  ```toml
  [patch.crates-io]
  unicode-width = { git = "https://git.sr.ht/~sajattack/unicode-width" }
  ```
* C runtime intrinsics (`memset`, `memcpy`, `memmove`, `memcmp`, `strlen`)
  are provided directly in `psp/src/alloc_impl.rs` using non-recursive loops.

3. PSP-3000 MEMORY ARCHITECTURE & `MEMSIZE=1` FINDING
----------------------------------------------------------------------
* Hardware Memory Layout:
  - PSP-1000 (Fat): 32 MiB total main RAM (~24 MiB user partition 2).
  - PSP-2000/3000/Go (Slim): 64 MiB total main RAM (~52-56 MiB user partition 2
    WHEN unlocked by `MEMSIZE=1` in `PARAM.SFO`).
  - Video RAM (EDRAM): 2 MiB (`0x04000000`, managed via `psp::vram_alloc`).
    * At 480x272 (`BUF_WIDTH = 512`), `Psm8888` draw + display buffers take
      `512 * 272 * 4 * 2 = 1,114,112` bytes (~1.06 MiB), plus `Psm4444` (or
      16-bit) Z-buffer `512 * 272 * 2 = 278,528` bytes (~272 KiB) = ~1.33 MiB,
      leaving ~684 KiB of EDRAM for active texture caching.
    * Switching framebuffers to 16-bit (`Psm5650` / `Psm5551`) cuts framebuffer
      VRAM to `512 * 272 * 2 * 2 = 557,056` bytes (~544 KiB), leaving ~1.19 MiB
      of EDRAM for textures.
* CRITICAL DISCOVERY IN `cargo-psp`'s `mksfo`:
  - Inspecting `cargo-psp/src/bin/mksfo.rs` at `e4cc06f6fa50fa45dc3ae8b332e8a2b67625f588`
    (lines 155-214) revealed that `mksfo`'s hardcoded `valid` key table omits
    `"MEMSIZE"` (`EntryType::Dword`), whereas `psp_ref/Makefile.psp` line 461
    explicitly runs:
    `mksfoex -d MEMSIZE=1 "Majora's Mask PSP Port" .../PARAM.SFO`
  - Without `MEMSIZE=1` in `PARAM.SFO`, a PSP-3000 or PPSSPP (even in Slim
    64 MiB mode) restricts User Partition 2 to the 24 MiB PSP-1000 ceiling!
  - Solution for our project:
    1) Vendor or clone `AndrewAltimit/rust-psp` @ `e4cc06f6fa50fa45dc3ae8b332e8a2b67625f588`
       into `tools/rust-psp` (gitignored or tracked per repo-local dependency
       plan) OR patch `mksfo.rs` / post-pack `PARAM.SFO` with `-d MEMSIZE=1`
       and `pack-pbp` so `EBOOT.PBP` always carries `MEMSIZE=1`.
    2) In Step 01, Flash will measure `sceKernelTotalFreeMemSize()` and
       `sceKernelMaxFreeMemSize()` both before and after setting `MEMSIZE=1`
       in `PARAM.SFO` so we have exact empirical proof of available user RAM.

4. LOW-LEVEL I/O, PATHS, AND ASSET RESTRICTIONS
----------------------------------------------------------------------
* Working Directory Initialization:
  - In `AndrewAltimit/rust-psp` (`psp/src/lib.rs` lines 74-99), `_start!` in
    `no_std` mode automatically parses `argv[0]`, strips the filename, and calls
    `sceIoChdir` to the directory containing `EBOOT.PBP` (e.g.,
    `ms0:/PSP/GAME/PocketMajora/` or `ef0:/PSP/GAME/PocketMajora/`).
  - Relative paths opened via `psp::io::File::open("boot_probe.log", ...)` or
    `sceIoOpen` resolve relative to the `EBOOT.PBP` launch directory!
* Chunked I/O Requirement (Learned from `psp_ref/src/port/psp/mm_psp_asset_builder.c`):
  - PSP Memory Stick (`ms0:`) and Go storage (`ef0:`) drivers can return short
    reads/writes or transient `0` bytes on large transfers. File I/O in Rust
    should loop in bounded chunks (e.g. `16 KiB` = `0x4000` bytes) with short
    retry delays (`sceKernelDelayThread(1000)`).
